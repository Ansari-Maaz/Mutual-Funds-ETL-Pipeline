Counting rules. “With NAV” counts a fund once if it has at least one stored NAV observation. “Without NAV” means no NAV observation is stored for that fund. Countries use the project's public three-letter country display codes. Funds without a recorded domicile are listed separately.

Holdings are currently stored for US funds only. Holdings are counted at the fund-record level; SEC N-PORT filings are series-level and may be shared across related share classes. NAV and holdings availability reflects the local database snapshot, not live source availability.

Interpretation. “With holdings” means at least one position row is stored for that US fund record. “Without holdings” means no position rows are currently stored. It does not prove that the fund publishes no portfolio holdings.

A5 | HOW TO USE THE API

Make a data request

1. Choose the API base URL. Local development uses http://localhost:3001. For a hosted deployment, use the API service's assigned public base URL.

2. Search for a fund. No key is needed for read requests. This example searches US funds with NAV; `USA` and `US` are both accepted.

curl 'http://localhost:3001/api/v1/funds?country=USA&has_nav=true&page=1&limit=25'

The response includes fund IDs. Use an ID from the search result in follow-up requests:

curl 'http://localhost:3001/api/v1/funds/{fund_id}'
curl 'http://localhost:3001/api/v1/funds/{fund_id}/nav?limit=5'
curl 'http://localhost:3001/api/v1/funds/{fund_id}/holdings?limit=100'
curl 'http://localhost:3001/api/v1/funds/{fund_id}/profile-data'
curl 'http://localhost:3001/api/v1/funds/{fund_id}/completeness'

3. Check API docs and service health.

Open in a browser: http://localhost:3001/api/docs
OpenAPI JSON:      http://localhost:3001/api/openapi.json
API health:        http://localhost:3001/health
Database health:   http://localhost:3001/api/v1/health/database

4. Use protected operations only when authorized. Source checks and ETL run creation need the server's admin key. Keep it out of URLs, public frontend code, screenshots, and committed files.

curl -X POST 'http://localhost:3001/api/v1/etl/runs' \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: <ADMIN_API_KEY>' \
  -d '{"sourceIds":["sec_open_end_fund_classes"]}'

Errors: API validation errors return a JSON error object with a stable code/message. Check the HTTP status; database or source errors are not represented as empty successful results.
