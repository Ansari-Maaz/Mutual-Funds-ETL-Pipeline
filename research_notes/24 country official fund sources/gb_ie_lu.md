# Official fund-data sources: United Kingdom, Ireland, Luxembourg (research date 2026-11-18)

Legend: VERIFIED = fetched this session with real response; UNVERIFIED = from background knowledge/search snippet only; UNOFFICIAL = not regulator/exchange/association/authority. All curl tests used a normal Chrome User-Agent from the project host. Scratch data in /tmp/r1 (not in repo). No repo code edited.

## 1. Integrated sources and why they under-deliver

### Takeaway
All three countries are loaded as name-only fund masters (FCA CSV, CBI PDF, BDE CSV) plus tiny NAV snapshots (Allianz, Euronext, FT, FundsLibrary). The fastest large win is ESMA FIRDS (ISIN/CFI/currency/LEI for about 6-7k IE and LU share classes and 40-odd GB), ESMA cross-border register (manager/status/inception for 5.8k IE and 13.6k LU UCITS), the HMRC reporting-funds list (ISIN for about 38.6k IE and 59.5k LU lines, all-time) and GLEIF (IE only). Official bulk NAV history and holdings do not exist for any of the three regulators; they only come from manager files (ETF issuers) and paid LuxSE/Euronext data.

### Cited Findings (code read + local data + live checks)
- fca.py: downloads one FOI annex CSV `https://www.fca.org.uk/publication/fca/foi2026_01166-annex-a.csv` (one-off FOI release, not a stable feed; 2,099,836 bytes in reports/fca_dataset_manifest.json). Columns VERIFIED locally: FRN, Operator Name, PRN, Fund Name, Fund other names, Status, Effective Date, Fund Structure, Scheme Type, Product Type, Umbrella Name. 11,842 rows: Recognised 7,867 (overseas, deliberately dropped by connector), Approved 3,168, Authorised 807; Sub-Fund 10,973. Connector emits only manager, category (scheme type), status; currency/isin always None. This explains GB 4,261 funds, ISIN 33, NAV 286. The FOI URL is likely to go stale; no ISIN column exists.
- uk_ft_morningstar.py / uk_fundslibrary.py: read local snapshot CSVs (data/raw/united_kingdom/ft_morningstar_fund_prices.csv and fundslibrary_unit_prices.csv) - these files are NOT present in data/raw/united_kingdom this session (only fca_fund_register.csv). One NAV row per fund (single date), FT URL has date-stamped documentKey `688_UTS~Combined_261024`. Both UNOFFICIAL (FT/ICE, FundsLibrary), "terms to confirm". They are the only source of GB NAV (286) and ISIN (33).
- central_bank_ireland.py: scrapes ASP.NET postback on `https://registers.centralbank.ie/downloadspage.aspx` for the Authorised UCITS PDF; parses name by "line above date" heuristic; source_fund_id is sha256 of name; currency/ISIN None. Result: 6,725 IE rows with name only. Download page VERIFIED live, lists registers "as at" 16 Nov 2026 (ICAV, Designated Investment Companies, Unit Trusts, CCF, ILP), AIFM 13 Nov, UCITS ManCos 13 Nov, UCITS PDF, ICAV register. No machine-readable (CSV/XLS) fund-level file on the page. — [CBI downloads](https://registers.centralbank.ie/downloadspage.aspx)
- lu_allianz_daily_nav.py: reads local CSV data/raw/luxembourg/allianz_luxembourg_daily_nav.csv (file absent this session) scraped from `https://regulatory.allianzgi.com/en-gb/facilities-services/luxemburg-en/funds/mutual-funds` (HTTP 200, 63 KB HTML, VERIFIED). One NAV per ISIN share class; Allianz only.
- lu_euronext_funds.py + euronext_base.py: read local snapshot euronext_luxembourg_funds.csv (absent); category is a keyword heuristic on the fund name (UNRELIABLE, not official classification). The source URL live.euronext.com/en/products/funds/list is a JS page; `live.euronext.com/en/ajax/getDetailedQuote/<ISIN-MIC>` returned an encrypted `{"ct":...}` JSON blob (VERIFIED) so it is not directly parseable.
- bde_european_funds.py (LU): Banco de Espana CSV `.../listas-fondos-inversion-pais/lista-if-lu.csv` (31.2 MB). VERIFIED locally: 31,214 rows, columns EUROPEAN CODE (LUO...), LEI (only 20,261 filled), FUND NAME, MANAGEMENT NAME, ADDRESS, INVESTMENT POLICY (Equities 8,280, blank 7,964, Other 4,635, Mixed 4,118, Bonds 3,539, Real estate 1,784, Hedge 894), CAPITAL VARIABILITY. This is the ECB-style fund list (Banco de Espana republishes ECB/ESCB IFs register); it supplies manager (16,824 in DB) and investment-policy category, but no ISIN, no currency (DB sets currency by default), no NAV. It is a central-bank (official) source but not ISIN-bearing.
- DB state (00_current_db_coverage.md, 2026-11-17): GB 4,261 funds NAV 286 ISIN 33 mgr 3,975 cat 4,261; IE 6,725 funds, nothing but name/currency; LU 25,901 funds NAV 1,944 ISIN 49 mgr 16,824 cat 1,944.
- reports manifests: fca (2026-11-16), cbi (2026-11-16, 675,786-byte PDF), lu_bde (31,257,215 bytes) all downloaded=false (cache reuse) - i.e. connectors re-use cached files, no change detection of the live register.

### Inferences
- LU fund IDs are sub-fund level (LUO code); NAV/ISIN are per share class, so a share-class table (or fund_profile_snapshots JSON) is required to hold FIRDS/HMRC ISINs; matching to BDE sub-funds needs LEI or name normalisation.
- 7,867 FCA "Recognised" rows are overseas (mostly IE/LU/other) UCITS marketed in the UK; they are a free bridge from IE/LU sub-fund names to FCA PRNs and umbrella names.

### Gaps
- Local snapshot CSVs for FT/FundsLibrary/Allianz/Euronext not present so row counts not verified; how they were originally scraped not in connector code.

## 4. Concrete connector design

### Takeaway
Build three new bulk connectors (ESMA FIRDS+cbdif, HMRC reporting funds, GLEIF) feeding a share-class level ISIN bridge, add CBI register PDFs and CSSF UCITS identifiers, and add issuer holdings connectors for ETFs.

### Cited Findings (design; all endpoints above verified)
1. `esma_firds_funds` (country GB/IE/LU by ISIN prefix; id `isin`): list weekly `FULINS_C` via firds_files Solr; download latest from `download_link`; stream-parse XML; keep ISINs with prefix in {IE, LU, GB} and CFI "C*"; merge duplicate venue rows (min FrstTradDt as listing date, venue list). Output: isin, name, cfi, currency, issuer LEI, mic. Optional second `fca_firds` from `data.fca.org.uk/artefacts/FIRDS` to add UK venue lines. Cadence weekly; ~100-200 MB XML, fine for streaming (use iterparse).
